--------------------------------------------------------------------------------
1. SYSTEM OVERVIEW
--------------------------------------------------------------------------------
EduAttend is a school attendance monitoring system for K-12 schools
(Grades 7-12). It allows administrators to manage accounts, schedules,
rooms, and student records; teachers to conduct QR-based attendance
sessions; and students to view their own attendance history.

The application runs as a hybrid Blazor/MAUI app:
  * UI            : Blazor components (Components/Pages/*.razor)
  * Business logic: Services/*.cs (AuthService, AttendanceSessionService,
                    ReportService, AnalyticsService, AuditService, etc.)
  * Data access   : Data/SchoolDbContext.cs + switchable DB context factory
                    (MySQL School_sms, or portable SQLite demo database)
  * Auth          : Username/password login with PBKDF2-SHA256 hashed
                    passwords, Remember-me session persistence, audit-logged

--------------------------------------------------------------------------------
2. HOW THE SYSTEM WORKS
--------------------------------------------------------------------------------
STEP 1 - LAUNCH & DATABASE SELECTION
    On the login screen the user first selects a DATABASE CONNECTION
    profile:
       * "School_sms" (MySQL)  -> real school data seeded via seed_data.sql /
                                  seed_full.sql (Server=localhost, DB=School_sms)
       * Portable demo profile -> local SQLite file auto-seeded on first run
                                  with random demo data (200 teachers,
                                  200 students, 200 rooms, 20 sections)

STEP 2 - LOGIN
    The user enters a USERNAME and PASSWORD.
    Validation flow (Services/AuthService.cs):
       1. Look up user by username.
       2. Reject if status is LOCKED or INACTIVE, or CanLogin = false.
       3. Verify password against stored PBKDF2$100000$salt$hash record
          (constant-time comparison).
       4. On success a UserSession (UserId, Username, Role, DisplayName) is
          created; "Remember me" persists it locally.
       5. Every login/logout is written to the AUDIT LOG.

STEP 3 - ROLE-BASED REDIRECTION
    After login the user lands on the dashboard for their role:
       * SUPERADMIN -> /dashboard          (Admin Dashboard)
       * TEACHER    -> /teacher/dashboard  (Teacher Dashboard)
       * STUDENT    -> /student/dashboard  (Student Dashboard)
    The sidebar navigation menu (NavMenu.razor) shows only the pages
    permitted to the logged-in role.

STEP 4 - DAILY ATTENDANCE FLOW (QR-BASED)
    1. Admin defines rooms, subjects, teachers, students, and class
       schedules (subject + section + room + day/time).
    2. Each student has a QR code (QRCodes page / student_qr_tbl).
    3. A teacher opens START SESSION during their scheduled class.
    4. Students scan their QR codes (html5-qrcode camera scanner).
    5. Records are written to attendance_sessions + attendance_records
       (Present/Absent/Late/Excused).
    6. Reports, analytics, and exports are generated from these records.
    7. Teachers can also file leave requests which mark sessions Excused.

STEP 5 - SECURITY & AUDITING
    * Passwords are never stored in plain text (PBKDF2-SHA256, 100k iterations).
    * All significant actions (logins, CRUD operations, exports) are recorded
      in the audit_logs table and viewable on the Audit Log page.
    * Accounts can be deactivated/locked by the admin (status/can_login flags).
    * Sensitive fields are encrypted in the database with AES-256-GCM
      (Data/DataEncryption.cs): student address, guardian name/contact and
      contact no.; teacher email and contact no.; leave and excuse reasons,
      review notes and attachments; audit-log details. Names and LRN stay
      plain so search and sorting keep working.
    * Values are decrypted only inside the app, so pages, reports and
      CSV/Excel exports show plain text. A tampered value, or one written
      with a different key, shows as "[unable to decrypt]".
    * Key: Encryption:DataKey in appsettings.json (base64, 32 bytes), or the
      EDUATTEND_DATA_KEY environment variable, which takes precedence. Every
      install sharing a database needs the same key; data encrypted with a
      lost key cannot be recovered.
    * Rows saved before encryption was enabled stay readable and are
      encrypted on their next save, or all at once via Settings > Data
      encryption > "Encrypt existing records" (audit-logged).

3. USER ROLES
--------------------------------------------------------------------------------
ROLE 1: SUPERADMIN (System Administrator)
    Full control of the system. Only role that can manage accounts,
    rooms, master data, and view the audit log.
    Menus : Dashboard, Students, Teachers, Schedules, Rooms, Accounts,
            Admin Analytics, Live Monitoring, Leave Requests, Audit Log,
            Reports, Export Data, Notifications, Profile Settings.

ROLE 2: TEACHER
    Conducts classes and takes attendance.
    Menus : Dashboard, My Schedule, Handled Sections, Start Session
            (QR scanning), Attendance History, My Attendance, Analytics,
            File Leave Requests, Notifications, Profile Settings.

ROLE 3: STUDENT
    Views personal attendance information only.
    Menus : Dashboard, Attendance History, Notifications, Profile Settings.

SUMMARY TABLE
+------------+---------------------------+------------------------------------+
| Role       | Purpose                   | Key Permissions                    |
+------------+---------------------------+------------------------------------+
| SUPERADMIN | System administration     | Manage ALL data + accounts + audit |
| TEACHER    | Class attendance taking   | Sessions, QR scanning, reports     |
| STUDENT    | View own attendance       | Read-only personal history         |
+------------+---------------------------+------------------------------------+

5. SYSTEM FEATURES
--------------------------------------------------------------------------------
ADMIN (SUPERADMIN) FEATURES
   * Admin Dashboard     - overview statistics of the whole school
   * Student Management  - add/edit/deactivate students, guardian info,
                           LRN, student numbers (Students page)
   * Teacher Management  - add/edit teachers, subject assignments
                           (Teachers page)
   * Schedule Management - subject-section-room-day-time blocks
                           (Schedules page)
   * Room Management     - 25 pre-loaded rooms incl. labs, gym, auditorium
                           (Rooms page)
   * Account Management  - create user logins, set roles/status/can_login,
                           reset credentials (Accounts page)
   * Admin Analytics     - attendance trends, charts across grade levels
                           (AdminAnalytics page)
   * Live Monitoring     - watch running attendance sessions in real time
                           (LiveMonitoring page)
   * Leave Requests      - review leave requests filed by teachers
                           (LeaveRequests page)
   * Audit Log           - who did what and when (AuditLog page)
   * Reports             - attendance report generation (Reports page)
   * Export Data         - CSV/data exports (ExportData page)

TEACHER FEATURES
   * Teacher Dashboard    - today's classes and quick stats
   * My Schedule          - weekly teaching timetable
   * Handled Sections     - sections/classes assigned to the teacher
   * Start Session        - open an attendance session and scan student QR
                            codes live (camera-based html5-qrcode scanner)
   * Attendance History   - past session records, per-student breakdown
   * My Attendance        - teacher's own attendance log
   * Analytics            - class attendance insights and charts
   * File Leave Requests  - request leave for excused sessions
   * Notifications        - announcements/system alerts
   * Profile Settings     - update personal information/password

STUDENT FEATURES
   * Student Dashboard    - personal attendance summary
   * Attendance History   - complete history per subject/class
   * Notifications        - announcements/system alerts
   * Profile Settings     - update personal information/password
   * QR Code              - student identity QR scanned into sessions
                            (generated from student_qr_tbl)

SHARED / CROSS-CUTTING FEATURES
   * Dark/light theme support
   * Collapsible sidebar navigation, responsive layout
   * Chart.js visualisations (chart.umd.js bundled locally)
   * Multi-database profiles (MySQL production vs offline SQLite demo)
   * Persistent sessions ("Remember me")
   * Full audit trail of sensitive actions
   * CSV export of data
